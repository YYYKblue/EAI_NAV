# 建图、安全框和地图 YAML 逐参数说明

本文覆盖：

- `config/mapping/gmapping.yaml` 的 30 个参数；
- `config/safety/box_filter.yaml` 的 7 个参数；
- `config/safety/box_filter_2.yaml` 的 7 个参数；
- `maps/bj050101.yaml` 的 6 个地图元数据参数。

## 1. `config/mapping/gmapping.yaml`

### 1.1 文件作用

`mapping.launch` 启动 `slam_gmapping`，加载本文件，然后由 launch 另外设置：

```text
base_frame = base_footprint
odom_frame = odom_combined
map_frame  = map
scan       -> /scan（默认）
```

Gmapping 只使用主激光 `/scan` 建图，不直接融合 `/scan_2` 和 `/scan_3`。三台激光同时进入导航 Costmap，是另一条独立数据链。

Gmapping 是 Rao-Blackwellized particle filter SLAM：每个粒子包含一条机器人轨迹和一份条件地图；里程计先预测粒子，激光扫描匹配再修正并更新权重，必要时重采样。

### 1.2 地图发布和激光量程

| 参数 | 当前值 | 类型/单位 | 详细含义与当前效果 |
|---|---:|---|---|
| `map_update_interval` | `1.0` | s | 重新生成并发布 ROS OccupancyGrid `/map` 的最小时间间隔。它不限制内部每帧激光的粒子更新；设小主要增加地图转换与发布开销。 |
| `maxUrange` | `8.0` | m | ScanMatcher 的最大“可用”激光距离。用于扫描匹配和地图更新的命中信息会在此尺度受限。应不大于 `maxRange`，并落在雷达可靠量程内。 |
| `maxRange` | `10.0` | m | Gmapping 认为的激光最大考虑范围。远于该范围的读数不应被当作可靠障碍命中；介于 `maxUrange` 与 `maxRange` 的射线可用于表示远处未命中/自由空间语义，具体裁剪由 Gmapping 实现。 |

当前 YDLidar 的 `LaserScan.range_max` 配为 16 m，但三条链路对量程的使用不同：

| 使用者 | 当前范围 | 目的 |
|---|---:|---|
| AMCL | `laser_max_range = 6.0 m` | 地图定位匹配 |
| Costmap | `obstacle_range = 2.0 m` | 标记实时障碍 |
| Costmap | `raytrace_range = 5.0 m` | 清除自由空间 |
| Gmapping | `maxUrange = 8.0 m` | 扫描匹配/有效建图尺度 |
| Gmapping | `maxRange = 10.0 m` | 最大考虑尺度 |
| 雷达消息 | `range_max = 16.0 m` | 驱动上报边界 |

这些值不要求完全相等，因为任务不同，但都必须小于实际环境中雷达的可靠量程。把驱动宣称的理论最大值直接用于建图，可能把远距离噪声写进地图。

### 1.3 扫描匹配搜索

| 参数 | 当前值 | 类型/单位 | 详细含义与当前效果 |
|---|---:|---|---|
| `sigma` | `0.05` | 匹配评分尺度 | 贪心端点匹配的高斯评分尺度。实现按端点与候选占据栅格均值的距离计算指数分数；虽然名为 sigma，不宜直接当成雷达说明书中的测距标准差。增大使偏离仍有较高分，减小使匹配更尖锐。 |
| `kernelSize` | `3` | int，栅格索引半径 | 对每个激光端点，在预计栅格周围 `[-3,+3]` 的 X/Y 索引内寻找最佳占据对应点，即最多检查约 `7×7` 邻域；在 0.05 m 地图上单轴范围约 ±0.15 m。增大提高容错同时显著增加匹配计算。 |
| `lstep` | `0.05` | m | 贪心位姿优化的初始平移搜索步长。优化比较当前位置及 X/Y 正负方向候选。 |
| `astep` | `0.05` | rad，约 2.86° | 贪心位姿优化的初始角度搜索步长。 |
| `iterations` | `5` | int | 扫描匹配递归优化次数。搜索在没有改进时逐步缩小步长；次数越多局部精修更充分、CPU 更高，但不能解决很差的初始里程计猜测。 |
| `lsigma` | `0.075` | 似然尺度 | 单束激光在粒子权重似然计算中的距离尺度，与上面的贪心匹配 `sigma` 分工不同。减小会让粒子间权重差异更尖锐。 |
| `ogain` | `3.0` | 正数，平滑系数 | 观测似然归一化的平滑增益，用来减轻大量激光束和粒子数造成的权重过度集中。Gmapping 实现中的增益与该值和粒子数相关；增大通常会压平粒子权重差异、降低频繁重采样倾向。 |
| `lskip` | `0` | int，束间隔控制 | 计算匹配似然时跳过的激光束数量。0 表示不主动跳束、使用所有合格束；增大可降 CPU，但会损失几何信息。 |
| `minimumScore` | `30` | 扫描匹配分数 | 只有扫描匹配得分高于此阈值，才接受匹配后的粒子位姿修正；低于阈值时保留里程计预测位姿并报告匹配失败。分数随有效束数和场景变化，不能跨雷达配置机械比较。过高会频繁退回纯里程计，过低会接受错误匹配。 |

`sigma`、`lsigma`、`minimumScore` 强耦合。调整激光视场、束数、`lskip` 或有效量程后，原来的 score 分布可能改变，应先记录 Gmapping 输出的 `Average Scan Matching Score` 再确定阈值。

### 1.4 里程计运动噪声模型

| 参数 | 当前值 | 类型 | 详细含义与当前效果 |
|---|---:|---|---|
| `srr` | `0.01` | 噪声系数 | 平移运动量对平移噪声的贡献，即 translation/translation。 |
| `srt` | `0.02` | 噪声系数 | 旋转运动量对平移噪声的贡献，即 translation/rotation。原地转动打滑造成位置漂移主要反映在这里。 |
| `str` | `0.01` | 噪声系数 | 平移运动量对旋转噪声的贡献，即 rotation/translation。直行时航向漂移主要反映在这里。 |
| `stt` | `0.02` | 噪声系数 | 旋转运动量对旋转噪声的贡献，即 rotation/rotation。 |

命名可按“第一字母是噪声结果、第二字母是运动来源”记忆。这里的数值与 AMCL `odom_alpha1～4` 属于两个不同实现，不能直接照搬或一一等值。噪声过小会让粒子缺少覆盖真实位姿的多样性，过大则会使扫描匹配更难、地图模糊。

### 1.5 触发更新、重采样和粒子数

| 参数 | 当前值 | 类型/单位 | 详细含义与当前效果 |
|---|---:|---|---|
| `linearUpdate` | `0.05` | m | 自上次处理后累计平移超过 0.05 m，就允许处理新扫描。当前阈值很小，建图更新密集。 |
| `angularUpdate` | `0.0436` | rad，约 2.50° | 累计旋转超过约 2.5° 即处理新扫描。与线性阈值是“任一满足即可”的触发关系。 |
| `temporalUpdate` | `-1.0` | s | 仅由时间强制处理扫描的周期。负值关闭时间触发，所以机器人完全静止时不会因为时间流逝反复更新同一位置；仍可由运动阈值触发。 |
| `resampleThreshold` | `0.5` | 粒子比例 | 当有效粒子数 `N_eff < 0.5 × particles` 时重采样。当前 50 粒子时阈值约为 25。增大更容易重采样，减小则保留退化权重更久。 |
| `particles` | `50` | int，粒子数 | Gmapping 固定粒子数。每个粒子维护地图/轨迹结构，数量增加会明显提高内存和 CPU，但对高里程计噪声、多假设环境更稳健。 |

Gmapping 的 `particles: 50` 与 AMCL 的 `2000～5000` 不矛盾：Gmapping 每个粒子带地图，单粒子成本远高于只在已知地图上定位的 AMCL 粒子。

### 1.6 地图初始范围和分辨率

| 参数 | 当前值 | 类型/单位 | 详细含义与当前效果 |
|---|---:|---|---|
| `xmin` | `-1.0` | m | 初始地图最小 X。 |
| `ymin` | `-1.0` | m | 初始地图最小 Y。 |
| `xmax` | `1.0` | m | 初始地图最大 X。 |
| `ymax` | `1.0` | m | 初始地图最大 Y。 |
| `delta` | `0.05` | m/cell | Gmapping 地图栅格分辨率 5 cm，与导航 Costmap 和保存地图的分辨率一致。减半到 0.025 m 会使同样面积栅格数约变为 4 倍。 |

初始地图是约 `2 m × 2 m`，即约 `40 × 40` cells。Gmapping 的地图结构会在机器人/扫描超出边界时扩展，因此这四个边界不是最终可建图面积限制；初始范围过大反而会增加不必要的初始地图处理。

### 1.7 粒子位姿似然采样

| 参数 | 当前值 | 类型/单位 | 详细含义与当前效果 |
|---|---:|---|---|
| `llsamplerange` | `0.01` | m | 计算局部似然时围绕候选位姿进行平移采样的范围。 |
| `llsamplestep` | `0.01` | m | 平移似然采样步长。当前步长等于范围，采样较稀。必须为正且不应大于到完全失去有效采样的程度。 |
| `lasamplerange` | `0.005` | rad，约 0.286° | 局部似然的角度采样范围。 |
| `lasamplestep` | `0.005` | rad，约 0.286° | 角度似然采样步长，当前同样等于范围。 |

这四项用于粒子位姿周围的似然评估，不是主贪心扫描匹配的 `lstep/astep`。扩大范围或减小步长会增加采样点数和计算量；只有当里程计预测与扫描匹配误差统计支持时才应调整。

## 2. 激光安全框的代码行为

两个 YAML 都由同一个 `scripts/laser_safety_gate.py` 读取。节点对每帧 LaserScan 执行：

1. 在该扫描的时间戳查询 `scan.header.frame_id -> box_frame` 的 TF。
2. 对每个有限且位于消息 `range_min～range_max` 内的距离，按扫描角度生成激光坐标系中的 `(x,y,0)` 点。
3. 用完整三维旋转和平移把点变换到 `box_frame`。
4. 对 X、Y、Z 同时进行包含边界的闭区间判断。
5. 把框内点数作为 `std_msgs/Int16` 发布，最大饱和为 32767。

安全节点自身没有速度输入、没有 `cmd_vel` 输出、没有阈值参数，也没有布尔判定逻辑，因此它的直接功能只是“框内点计数”。不过 `base.launch` 同时启动的 `dashgo_driver` 会消费这两个计数并对正向线速度做门控，完整链路见第 5 节。

## 3. `config/safety/box_filter.yaml`

### 3.1 话题关系

第一个节点没有 remap：

```text
订阅：/scan
发布：/is_passed
frame：laser_frame -> base_footprint
```

### 3.2 每个参数

| 参数 | 当前值 | 类型/单位 | 详细含义与当前效果 |
|---|---:|---|---|
| `box_frame` | `base_footprint` | frame ID | 所有点变换到该坐标系后再判断盒体。代码对此项有同名默认值，但 YAML 显式配置更清楚。 |
| `max_x` | `0.45` | m | 盒体最前端，X 正方向。比 polygon 前缘 0.283 m 向前多 0.167 m。边界上的点也计数。 |
| `max_y` | `0.3` | m | 左侧边界。比 polygon 左缘多 0.017 m。 |
| `max_z` | `0.5` | m | 上边界。主激光扫描平面 Z 约 0.28 m，在范围内。 |
| `min_x` | `0.1` | m | 盒体后端。它位于 polygon 内部，所以 `[0.1,0.283]` 的 X 区间与机器人外形重叠。 |
| `min_y` | `-0.3` | m | 右侧边界。盒体总宽 0.6 m。 |
| `min_z` | `0.05` | m | 下边界。盒体总高 0.45 m。 |

盒体尺寸：

```text
X 长度 = 0.45 - 0.10 = 0.35 m
Y 宽度 = 0.30 - (-0.30) = 0.60 m
Z 高度 = 0.50 - 0.05 = 0.45 m
```

对于理想水平二维主激光，所有点变换后 Z 约为 0.28 m，所以 Z 条件几乎总是通过，实际主要筛选 XY 前方矩形。若 TF 中加入 roll/pitch，点的 Z 会随扫描角度和距离变化。

## 4. `config/safety/box_filter_2.yaml`

### 4.1 话题关系

`move_base.launch` 对第二个节点做了 remap：

```text
订阅：/scan_2
发布：/is_passed_2
frame：laser_frame_2 -> base_footprint
```

### 4.2 每个参数

| 参数 | 当前值 | 类型/单位 | 详细含义与当前效果 |
|---|---:|---|---|
| `box_frame` | `base_footprint` | frame ID | 在机器人底面坐标系判断固定安全盒。 |
| `max_x` | `0.45` | m | 最前端，与第一个框一致，超出 polygon 前缘 0.167 m。 |
| `max_y` | `0.29` | m | 左边界，比 polygon 左缘多 0.007 m。 |
| `max_z` | `0.5` | m | 上边界。 |
| `min_x` | `0.17` | m | 后边界；`[0.17,0.283]` 与机器人 polygon 重叠，比第一个框少检查靠近机器人中心的 0.07 m。 |
| `min_y` | `-0.29` | m | 右边界，总宽 0.58 m。 |
| `min_z` | `0.02` | m | 下边界；低位激光安装 Z 约 0.05 m，处在范围内。 |

盒体尺寸：

```text
X 长度 = 0.45 - 0.17 = 0.28 m
Y 宽度 = 0.29 - (-0.29) = 0.58 m
Z 高度 = 0.50 - 0.02 = 0.48 m
```

`min_x/max_x` 等参数在代码中没有默认值；缺失任何一个会使节点初始化失败。还必须始终满足 `min_x <= max_x`、`min_y <= max_y`、`min_z <= max_z`，代码当前不会主动检查和报出更友好的错误。

## 5. 两个安全框的组合效果和驱动门控

| 项目 | 框 1 | 框 2 |
|---|---|---|
| 输入 | `/scan`，约 0.28 m 高 | `/scan_2`，约 0.05 m 高 |
| 输出 | `/is_passed` | `/is_passed_2` |
| 前方外伸 | polygon 前缘外 0.167 m | polygon 前缘外 0.167 m |
| X 与机身投影重叠 | 0.183 m | 0.113 m |
| 输出含义 | 框内有效点数 | 框内有效点数 |

`dashgo_driver/scripts/dashgo_driver.py` 的完整判断为：

```text
任一计数 > 2  -> 对后续正向命令令 x = 0
两个计数都 <= 2 -> 不因激光框限制正向 x
```

只修改 X 线速度，不修改角速度：

- 正向直行 `(x>0, theta=0)` 会变成停止平移；
- 正向转弯 `(x>0, theta!=0)` 会变成原地旋转；
- 倒车 `(x<0)` 不受这两个安全框限制；
- 原地旋转 `(x=0)` 不受限制。

阈值 `2` 写死在 `dashgo_driver.py`，不在这两个 YAML 中。安全计数的门控发生在驱动处理 `smoother_cmd_vel` 时；驱动发布的 `robot_cmd_vel` 调试/反馈消息在门控代码之前赋值，因此它可能显示未门控的输入命令，不能据此断定电机仍执行正向速度。

限制：

- `/scan_3` 高位激光没有启动第三个安全框节点。
- 仅启动 `mapping.launch` 时不会包含 `move_base.launch`，因此两个安全节点都不启动；它们只随 `navigation.launch` 或 `mapping_navigation.launch` 的 `move_base.launch` 启动。
- YAML 没有入侵阈值参数；驱动代码固定使用 `msg.data > 2`。
- 没有连续帧滤波，单点噪声会产生正计数。
- TF 查询失败时本帧直接不发布新值；驱动会保留上一次 bool 状态，没有超时转为禁止前进的 fail-safe 逻辑。
- 节点没有把“当前消息时间”或健康状态附加到 `Int16`，下游应另行监测话题频率。
- `safety_filters:=false` 时两个节点不启动，但驱动的状态初始为允许前进，因此等价于关闭此软件门控。
- 该软件门控没有硬件安全认证逻辑，不能替代急停、安全激光或独立安全控制器。

如果要把它提升为更可靠的制动链，应至少加入消息超时、雷达/TF 健康状态、连续帧滤波、正向与旋转扫掠区分、明确的输出速度话题和可测试的 fail-safe 默认值。仅把 `/is_passed` 改名或改成 bool 不能解决这些问题。

## 6. `maps/bj050101.yaml`

### 6.1 文件和地图范围

`navigation.launch` 默认把此文件传给 `map_server`。对应 PGM 是 `640 × 832` pixels，分辨率为 0.05 m/cell，因此地图物理尺寸为：

```text
X 宽度 = 640 × 0.05 = 32.0 m
Y 高度 = 832 × 0.05 = 41.6 m
```

### 6.2 每个参数

| 参数 | 当前值 | 类型/单位 | 详细含义与当前效果 |
|---|---:|---|---|
| `image` | `bj050101.pgm` | path | 地图像素文件路径。相对路径以 YAML 所在目录为基准，所以解析为 `maps/bj050101.pgm`。移动 YAML 时必须连同路径关系一起检查。 |
| `resolution` | `0.050000` | m/pixel | 每个像素代表 5 cm，与 Gmapping `delta` 和 Costmap `resolution` 一致。修改此值不会重采样图像，只会改变地图在现实中的比例。 |
| `origin` | `[-15.4, -29.8, 0.0]` | `[m,m,rad]` | 图像左下角在 `map` 坐标系中的 `[x,y,yaw]`。yaw 为 0 表示图像轴不相对地图旋转。由此地图大致覆盖 `x=[-15.4,16.6] m`、`y=[-29.8,11.8] m`。 |
| `negate` | `0` | bool-like int | 不反转灰度占据含义：黑色趋向占据，白色趋向自由。设为 1 会反转，通常会把墙和自由区对调。 |
| `occupied_thresh` | `0.65` | [0,1] 概率阈值 | 归一化占据值高于 0.65 的像素发布为占据 `100`。在 `negate=0` 的灰度图中，大致对应足够暗的像素。 |
| `free_thresh` | `0.196` | [0,1] 概率阈值 | 归一化占据值低于 0.196 的像素发布为自由 `0`。介于两个阈值之间的像素在默认 trinary 模式发布为未知 `-1`。必须满足 `free_thresh < occupied_thresh`。 |

对于 `negate: 0` 的灰度图，可用以下近似理解单通道像素 `color`：

```text
occupancy = (255 - color) / 255
occupancy > 0.65  -> occupied
occupancy < 0.196 -> free
其余              -> unknown
```

因此大致：灰度低于约 89 的像素为占据，高于约 205 的像素为自由，中间灰度为未知。实际边界比较和图像格式处理以当前 `map_server` 实现为准。

## 7. 保存新地图时的关系

使用 Gmapping 建图后，`map_saver` 会生成一对 `.pgm + .yaml`。替换当前地图时要一起替换，不能只替换 PGM。建议：

```bash
rosrun map_server map_saver -f /tmp/new_map map:=/map
```

验证新地图时重点检查：

- YAML 中 `image` 是否指向正确 PGM；
- `resolution` 是否仍为 0.05 m；
